# Footprint

A Flutter application for recording routes and exploring nearby areas. Free
recording works locally. The Explore screen adds distance-based walking loops,
ordered checkpoints, a persistent discovery map and three local achievements.

The interface follows the supplied Figma PDFs: a full-screen map, live recording
metrics, route naming and preview, and a searchable, sortable route catalog.
Stopping saves the route before opening the name editor; leaving that screen
never discards the recorded points. During recording, camera or library photos
can be pinned to the current location. Saved routes include photo markers and
a gallery with zoomable viewing and confirmed deletion.

## Development

Requires FVM, Flutter 3.47.2, and the platform tools for Android or iOS.

```sh
fvm use 3.47.2
make get
make verify
make run
```

The repository is a Dart pub workspace. Resolve dependencies from the root;
commit the root lockfile together with dependency changes.

## Verification

```sh
make test
make build-android
make build-ios
fvm flutter devices
make integration DEVICE=<simulator-or-device-id>
```

Tests cover domain values, GPS modes/recovery, recording failures and retries,
bounded geocoding, Cubits, SQLite CRUD/migrations/reopening, shutdown ordering,
widget states, and recording without a mounted map. A background-writer test
closes the UI database connection and verifies that subsequent samples survive.
The integration test uses native SQLite/files, simulated locations, local tiles,
and an injected image picker. Tests also cover photo cancellation, failed writes,
lost-selection recovery, deletion, and visual snapshots at large text sizes.

## Map Provider

The default is OpenStreetMap. Override the provider and its attribution together:

```sh
fvm flutter run \
  --dart-define='TILE_URL_TEMPLATE=https://your-provider.example/{z}/{x}/{y}.png' \
  --dart-define='TILE_ATTRIBUTION=Your provider attribution' \
  --dart-define='TILE_ATTRIBUTION_URL=https://your-provider.example/attribution'
```

The OSM development warning is informational. Failed downloads show a retry
banner; they are not hidden as successful transparent tiles. Check the
[OSM tile usage policy](https://operations.osmfoundation.org/policies/tiles/)
when selecting a provider.

## Walking Routes

Open **Explore** from the map. Distance selection uses a bottom sheet (1, 3, 5,
10 km, or a custom distance between 1 and 20 km). In A to B, select Start or
Destination and tap the map to set that point directly. The GPS button restores
the start to current location. Cancel or panning leaves existing points intact.
Routes are generated by **HeiGIT** (OpenRouteService). There are no fabricated
production routes.

For local development, obtain a key from the [HeiGIT account dashboard](https://account.heigit.org/).
Set `ORS_API_KEY` in an ignored `config/routing.local.json`
using the fields in `config/routing.example.json`, then run:

```sh
fvm flutter run --dart-define-from-file=config/routing.local.json
```

Stop any existing `flutter run` session before running this command. Dart defines
are build-time configuration; hot reload/restart cannot change them. A plain
`flutter run` does not load this JSON file or shell environment variables.
The default endpoint is `https://api.heigit.org/openrouteservice/v2/directions/foot-walking/geojson`.
The former `api.openrouteservice.org` endpoint is [deprecated](https://ask.openrouteservice.org/t/deprecating-api-openrouteservice-org-in-favour-of-api-heigit-org/7912).

Without routing configuration, recording, history and local discoveries still
work; generation reports its unavailable state. `ROUTING_URL` can point to an
HTTPS ORS-compatible proxy instead. It must accept the same walking request and
return GeoJSON. The proxy should own provider credentials, authentication and
quotas for distribution: **Dart defines are embedded in the app, not secret
storage**. Do not ship a private provider key in a release build.

The routing service receives the start and loop distance, or A/B coordinates, not
your recorded history. Discovery-based ranking is local. Checkpoints and cells
continue to be recorded without a routing connection; map tiles still have their
own network/cache requirements. The feature is not an offline map download.

Checkpoints are reached automatically in order. Reaching the last one marks the
walk completed; **Stop recording** still explicitly ends and saves the GPS session.
Stopping early preserves the route and discoveries without awarding completion.
Achievements are First walk, Explorer (10 areas) and Pathfinder (100 areas).

Progress starts with new recordings after the upgrade; historical routes are
not reprocessed. Cells represent visited areas, not fully explored streets or a
percentage of the city. Deleting a route keeps discoveries and achievements.
See [the exploration specification](docs/exploration.md) for limits and test coverage.

## Architecture And Status

See [ARCHITECTURE.md](ARCHITECTURE.md) for package responsibilities and the
Readflex conventions adopted here.

Android recording persists points in its foreground task before notifying the
UI. iOS uses app-owned recording with background location updates. Neither is a
promise of execution after force-stop; long background trips and real permission
flows still need physical-device testing.

The alternative grid catalog and sharing/export remain product work. Android
release builds still require production signing.

## Statistics

Open the chart icon in **Routes**. Statistics shows recorded distance, elapsed
recording time, recording count, and active days for Week / Month / All time.
Arrow controls browse previous weeks/months; future periods are disabled.
Select a chart bar for its exact date, distance, recording count, and duration.
The screen supports pull-to-refresh and refreshes when the app resumes.

Only completed recordings count, including older saved routes. A recording's
full distance/time belongs to its local start date, even across midnight; weeks
start on Monday. Time includes stops, and no walking/driving classification is
inferred. Deletion removes a recording from these totals. Exploration discoveries
and achievements remain separate and are not backfilled from old recordings.

Week/month charts show days. All time groups up to 24 months by month, then by
year for longer histories. SQLite v8 preserves existing data and lazily caches
completed-route summaries. GPS calculations run in an isolate, one trace at a
time, without a long write transaction or work added to Start/Stop recording.
Subsequent visits read the compact summaries; period changes need no database
queries. Statistics is local and does not call the routing API.

## Route Photos

Camera and library selection use `image_picker`. Photos are copied into the
application support directory; originals are never deleted or uploaded. Photo
pins use the GPS fix when a source is selected, not the image's EXIF location.
SQLite stores relative file names and a pending-capture journal. Android lost
picker results can be restored to the original route; failed copies can be
retried or discarded without losing route points. Orphan cleanup is restricted
to the app-owned photo directory and is retried on launch if it fails.

The iOS simulator has no camera; use Choose photo there. Camera permission flows,
HEIC selection, and Android activity destruction still need physical-device
validation. Details: [image_picker platform notes](https://pub.dev/packages/image_picker).
